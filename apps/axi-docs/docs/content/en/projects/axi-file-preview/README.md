# Axi File Preview (xlsx Dedup-Audit Viewer + Custom VideoPlayer)

> Source of truth: `/Volumes/code/workspace/candidates/axi-file-preview/`.
> Partition: `candidates/`. Branch: `feature/ci-check-design-tokens-entry`.
> Lifecycle: `prototype`. Owner: libu.

## Summary

Axi File Preview is a self-contained local web tool that ingests a dedup-audit
`audit.json` (produced by an external `daily dedup` script that scans two
external volumes on macOS) and renders the duplicate groups as three searchable
tabs (图片 / 视频 / 加密 .ts). The UI is an Ant Design 6.6 + React 19 + Vite 5.4
SPA built on the `@axi/core` / `@axi/crud` / `@axi/tokens` packages
(`link:` protocol to `foundation/axi-ui/packages/*`), with a single-file React
entry in `src/App.tsx` that hosts three sub-components — `ThumbCell`,
`DetailModal`, and the centerpiece **`VideoPlayer`** — plus a `Lightbox` that
opens on thumbnail click. The xlsx-report-renderer role is **not** a parser:
the heavy lifting lives in the external script that emits `audit.json`;
this tool simply ingests the JSON, splits rows into `img / vid / ts` buckets,
and renders them through `AxiTable` with live filter + pagination.

The custom `VideoPlayer` is a 700-line React component that intentionally
duplicates the native `<video>` feature surface (play / pause / vertical
volume popover / playback rate menu at 0.5×–2× / fullscreen / native PiP /
Document Picture-in-Picture with `x.com` branding / keyboard shortcuts /
auto-transcode fallback). It is the candidate contribution intended for
`@axi/ui/packages/widgets`. Media bytes are streamed by a custom Vite
middleware `serve-local-volume` that exposes `/__local/<encodedPath>` and
`/__transcode/<encodedPath>` for paths strictly under `/Volumes/` — the
middleware refuses anything outside that prefix and serves HTTP `Accept-Ranges`
bytes, then on `MEDIA_ERR_SRC_NOT_SUPPORTED` the player auto-switches to the
`__transcode` route which spawns `ffmpeg` (libx264 veryfast + AAC + faststart)
into a tmpdir cache keyed by `sha256(realpath + size + mtimeMs)`.

The renderer surface is read-only on the audit data and on disk. The tool is
**loopback-only** (`host: 127.0.0.1`, `strictPort: 5183`) because the
filesystem middleware has no auth — `AGENTS.md` and `README.md` are explicit
that the dev server must not be exposed to LAN. Promotion to `products/`
requires a `project-maturity-v1` review per `TASK.md` P3.

## Architecture Highlights

**Single-page React app, three tabs, group-by-group detail modal.** `App.tsx`
fetches `./audit.json` once on mount, then memoizes three flat row buckets
(`img / vid / ts`) derived from the `keep` field's file extension. `bucketOf(g)`
returns `'ts'` if the path matches `.ts` or `.d.mts` (the latter is excluded
from the video bucket because the audit pipeline reports TypeScript module
declarations under `*.d.mts` from the source directory). Each tab renders
through `AxiTable<any>` with columns `[id, 缩略图 (ThumbCell), 重复次数,
源文件路径 (mono), 详情]`. Live search filters by content / path / decision
or — when the query is purely numeric — by `idx`. The table uses
`storageKey: "dedup-audit-<tab>"` so column visibility persists per tab.
Per-tab pagination lives in `pageSizeByTab` so 50 / 50 / 50 stays independent
across tabs. The 「详情」 button opens a `DetailModal` showing the keep row
plus the cleanup list, both as paths (no lightbox) — actual media viewing
happens through the lightbox.

**Lightbox = unified carousel for image / video / `.ts`.** `Lightbox({list})`
listens for the `open-lightbox` `CustomEvent` dispatched by `ThumbCell` on
click, finds the matching thumb in the visible-filtered list, and renders
either `<VideoPlayer>` (when `isVideoPath(cur.path)`), an `<img>` (when
`IMG_EXT`), or a "加密 .ts 切片无法播放" placeholder (when `isTsPath(cur.path)`).
A `computeOptimal(w, h)` helper rotates the video 90° when the video aspect
is opposite the viewport aspect; `cycleRotate()` is user-overridable. Prev /
next navigation uses `pointerdown` (not just `click`) so the press animation
stays centered and the video/backdrop cannot swallow the event. Arrow keys
also navigate. The caption (`lb-info`) uses `wrapHover || isPaused` to fade
in/out — it never covers the video permanently.

**Custom VideoPlayer as native parity.** `VideoPlayer({path, poster, rotation,
onLoadedMeta, onClick, onHoverChange, onPausedChange})` owns its own
`HTMLVideoElement` ref + a wrapper ref. State: `playing`, `t`, `dur`,
`vol` (0–1, persisted under `axi-file-preview:player-volume`), `muted`
(persisted under `axi-file-preview:player-muted`), `rate`, `hovering`,
`loading`, `error`, `sourceUrl`, `isFs`, `isPip`, `volHover`, `rateOpen`.
Refs: `seekingRef`, `hideTimerRef`, `pipWindowRef`, `pipParentRef`,
`pipNextSiblingRef`. The error path auto-fallbacks to
`/__transcode/<encodedPath>` if the first `__local` URL returns
`MEDIA_ERR_SRC_NOT_SUPPORTED`. Picture-in-Picture has two paths: (a)
native `<video>.requestPictureInPicture()` and (b) Chrome Document PiP via
`window.documentPictureInPicture.requestWindow({width:520,height:320})`
which clones every `<link rel="stylesheet">` and `<style>` into the new
window, appends the player DOM node there, sets `x.com` branding, and
restores the node back to its original position on `pagehide`. Volume is a
vertical upward popover (`writing-mode: vertical-lr`, 32×110, semi-transparent
+ 12 px blur) anchored to a 36×36 button. Keyboard: `Space/k` toggle,
`m` mute, `f` fullscreen, `p` PiP, `←/j` seek −5/−10s, `→/l` seek +5/+10s,
`↑/↓` volume ±0.05.

**`serve-local-volume` middleware as the security boundary.** Two routes
mounted in `configureServer`: `/__local` (raw byte stream) and
`/__transcode` (ffmpeg-transcoded mp4). Both call `resolveVolumeFile` which
decodes the URL, rejects `..` or anything not starting with `/Volumes/`,
realpaths and re-checks the prefix, and `stat`s to ensure it's a file.
`sendFile` sets `Accept-Ranges: bytes`, parses `Range: bytes=start-end`,
and returns `206` with the requested byte range. The transcode cache is
keyed by `sha256(realpath + size + mtimeMs)` and persists at
`os.tmpdir()/axi-file-preview-transcode/`. Concurrent transcode requests
share the same promise (`transcodeJobs: Map<output, Promise>`), so two
tabs requesting the same `.avi` only spawn one `ffmpeg`. The ffmpeg
command is `-c:v libx264 -preset veryfast -pix_fmt yuv420p -c:a aac -b:a 128k
-movflags +faststart`, and the temp file is renamed into place on success.
MIME map covers mp4 / m4v / mov / webm / mkv / avi / wmv / flv / mpg /
mpeg / 3gp / mts / jpg / jpeg / png / gif / webp / bmp / heic / ico / ts.

**Audit schema as the data contract.** `audit.json` is a `{stats: {imgTotal,
vidTotal, tsTotal}, groups: [{keep: RowData | null, cleanup: RowData[]}]}`
document (schema v1 per `docs/HANDOFF.md`). `RowData` is
`{r, id, content, count: "×9", path: "/Volumes/.../...", note, image:
"group-001/foo.jpg" | null}`. The `previewLabel(content)` helper strips the
trailing `· 8-char-hex` dedup hash from the display label while preserving
it in the data model — added 2026-09-28 per `CHANGE.md`.

**`@axi/*` link dependencies and design-token discipline.** The four
`@axi/*` packages are linked by absolute path to `foundation/axi-ui/packages/*`,
so the project picks up the local dev build of the Axi design system without
a version pin. Two pnpm scripts (`check:design-tokens`, `check:ui-aesthetic`)
call into `foundation/axi-ui/scripts/*` to enforce the design system. Recent
git history is dominated by icon-system normalization (Picture / Video /
Lock inline SVGs, supplied fullscreen icon paths, X-style 32×32 hitboxes,
20×20 icon box, vertical volume capsule, rate menu blur).
