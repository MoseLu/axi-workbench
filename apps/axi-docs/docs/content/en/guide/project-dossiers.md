## What a dossier is

A dossier is the **read-only** Axi Docs surface for one project. The workspace index (`/Volumes/code/workspace/WORKSPACE_INDEX.md`) is the canonical list of dossiers; the build script `app/scripts/build-projects-index.mjs` regenerates them on demand.

## Path

- English: `docs/content/en/projects/<id>/`
- Simplified Chinese: `docs/content/zh/projects/<id>/`
- Locale mirror: identical relative paths, distinct `id` values in frontmatter.

The eight-piece structure (per `app/AGENTS.md`):

| File | Purpose |
| --- | --- |
| `README.md` | Dossier summary (purpose, stack, status, notes). |
| `AGENTS.md` | Read order, boundary, update cadence. |
| `INDEX.md` | Dossier index. |
| `TODO.md` | What Axi Docs still needs to surface. |
| `MILESTONE.md` | Dossier-level milestone and exit criteria. |
| `PRD.md` | Axi Docs' requirements for presenting the project. |
| `TDD.md` | Verification design for the dossier itself. |

## Source of truth

The project root always wins. The dossier is a pointer layer; it links to the project's own `AGENTS.md`, `README.md`, and verification commands rather than restating them.

## Build and verify

```bash
pnpm --dir app projects:build   # generate / refresh from WORKSPACE_INDEX.md
pnpm --dir app projects:check   # verify all 322 dossier files exist
```

`projects:build` is non-destructive: it skips existing files. The locale-level `INDEX.md` tables are always rewritten from the parsed workspace index.

## When to add a new dossier

Add nothing by hand. When a new active project appears in `WORKSPACE_INDEX.md` under one of the recognised sections (Core Active, Shared And Infrastructure Foundations, Reference Repos), re-running `projects:build` materialises the dossier automatically.

## When to edit a dossier by hand

Only when Axi Docs is the primary surface for the change (for example, documenting a cross-project MCP tool mapping, or describing how Axi Docs *consumes* the project). For project-internal changes, edit the project root and re-run `projects:build` to refresh the generated `README.md` summary if needed.

## Status lifecycle

- `draft` — generated scaffold; not yet reviewed.
- `published` — content has been read against the project root and verified.

The build script writes `status: draft` on first emission. Promotion to `published` is a deliberate hand-edit once the dossier has been cross-checked.

## 11-piece set (as of 2026-06-10)

The dossier was extended from 7 to **11 pieces** by [coverage audit 2026-06-10](../../axi-workspace-governance/audits/axi-docs-coverage-2026-06-10.md). The split:

- **Required (7 pieces)**: always generated by `projects:build`. Missing any of these fails `projects:check` with a non-zero exit.
- **Optional (4 pieces)**: generated only when the project root has the corresponding source file. Missing optional pieces do **not** fail the check; they are reported as warnings.
- **Passthrough (2 pieces)**: `CHANGE.md` and `CLAUDE.md` are copied verbatim with frontmatter prepended, when present at the project root.

| Group | Files | Behaviour |
| --- | --- | --- |
| Required | `README.md`, `AGENTS.md`, `INDEX.md`, `TODO.md`, `MILESTONE.md`, `PRD.md`, `TDD.md` | Always generated. |
| Optional | `CHANGELOG.md`, `SECURITY.md`, `README.zh-CN.md`, `AGENTS.zh-CN.md` | Generated only when project root has the source file. |
| Passthrough | `CHANGE.md`, `CLAUDE.md` | Copied verbatim (with frontmatter) when present. |

The 7 → 11 split is visible per-project in the dossier folder; for example, `axi-image-preview` has 12 files (the 7 required + 4 optional + `CHANGE.md` passthrough + an extra `AGENTS.zh-CN.md` alias).

## Hand-curated dossiers (preserved addenda)

`projects:build` regenerates the dossier from `WORKSPACE_INDEX.md`, but it also preserves hand-curated entries whose `status` field contains the literal string `hand-curated` (or `placeholder`). Two projects currently use this escape hatch:

- **dbskill** (`shared/`) — listed in `docs/projects.index.json` as `hand-curated mirror (not auto-generated)`. The dossier under `docs/content/{en,zh}/projects/dbskill/` is hand-curated because `dbskill` is not (yet) listed in `WORKSPACE_INDEX.md`.
- **codex-plus-app** (`tools/`) — listed as `hand-curated mirror (no face-level docs)`. The project has no `AGENTS.md` / `README.md` / `package.json`; the dossier is a 3-piece placeholder.

If you re-run `projects:build`, the JSON's `preservedAddenda` field lists which hand-curated entries survived the rebuild.

## Out of scope

- The dossier is **not** a copy of the project's documentation. Duplicate content drifts.
- The dossier is **not** the project PRD / TDD / MILESTONE — those live in the project root.
- The dossier is **not** translated content for the *project itself*. Per the root `AGENTS.md`, `references/*` is not translated. Dossiers are metadata about projects, not project content, so they are translated like any other Axi Docs page.
