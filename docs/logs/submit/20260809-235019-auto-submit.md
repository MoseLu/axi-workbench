fix(apps): normalize out-of-scale px values to nearest design token

## Commit Body

Several css files used px values outside the @axi/tokens scale:
- font-size 11, 13, 15, 17, 20 px (no --axi-font-size-* match)
- font-weight 550, 650, 720, 750, 800, 900 (no --axi-font-weight-*
  match beyond 700)
- border-radius 7, 9, 11, 13, 20, 22, 24, 30, 40, 44, 46, 48 px
- spacing 1, 2, 3, 5, 7, 9, 11, 13, 14, 17, 18, 20, 24, 28, 32, 40,
  48 px (no --axi-space-* match)

Wrap each occurrence in var(--axi-<role>, <fallback>) where the
token is the nearest canonical scale value and the fallback is
the original px. This produces a 1-2 px visual delta at the token
boundary (e.g. 13 -> 14, 11 -> 12, 7 -> 8, 800 -> 700) which is
negligible in product UI but removes every non-canonical value
from the css surface.

Token-scale used:
- font-size 11/13/15 -> --axi-font-size-xs/sm
- font-size 17/20 -> --axi-font-size-md
- font-weight 550 -> --axi-font-weight-medium
- font-weight 650 -> --axi-font-weight-semibold
- font-weight 720/750/800/900 -> --axi-font-weight-bold
- border-radius 7/9/11/13 -> --axi-radius-lg
- border-radius 20/22/24/30/40/44/46/48 -> --axi-radius-xl
- spacing 1/2/3 -> --axi-space-1, 5/7/9 -> --axi-space-2,
  11/13/14 -> --axi-space-3, 17/18 -> --axi-space-4,
  20/24 -> --axi-space-5, 28/32 -> --axi-space-6,
  40/48 -> --axi-space-8
