## Commit Body

Page-level css under apps/workbench/src/pages still had bare
px for the high-frequency values 4/8/10/12/16 (spacing),
4/6/8 (radius), and 400/500/600/700 (font-weight), despite
@axi/tokens already exposing --axi-space-{1,2,2-5,3,4},
--axi-radius-{sm,md,lg}, and --axi-font-weight-{normal,medium,
semibold,bold}.

Wrap each occurrence in var(--axi-*, <fallback>) so the design
system takes over once the page files start following the
canonical token scale; until then the fallback preserves the
current visual exactly.

Important: the script was rewritten mid-batch to correctly
handle multi-value declarations (e.g. padding: 12px 14px 20px)
where only some values are in the token scale. Earlier draft
left a stray 'px' suffix after the var() wrap, which produced
invalid CSS; that intermediate state was rolled back before
this commit.

Out-of-scale values (3, 5, 7, 9, 11, 13, 14, 20, 24, 28 px and
font-weight 550/650) are intentionally left as raw values
because there is no matching token; they should be consolidated
by design in a follow-up.
