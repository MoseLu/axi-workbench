## Commit Body

Adds the mobile approval gate so destructive actions surface as a pending approval and only proceed when the owner signs off via decideApproval. Low-risk mobile actions bypass the gate entirely and land directly.

packages/schemas/src/entities/control-plane.ts:
- TaskAssessmentSchema gains requiresApproval: z.boolean().default(false). Existing riskLevel / requiresAudit / requiresLibrarian semantics are unchanged; the new field is independent.
- ApprovalRequestSchema gains source: z.enum(['desktop', 'mobile_pairing']).default('desktop'), sourceDeviceId, projectId, idempotencyKey, actionType so the existing desktop approval surface can carry mobile provenance without breaking compatibility.

services/control-plane/src/control-plane.mjs:
- assessTask now sets requiresApproval: risk === 'destructive'. assessReadOnlyRegisteredCommand + assessAxiAgentTask explicitly set requiresApproval: false (registered read-only commands and Axi Agent tool-result lookups are not destructive by definition).
- createControlJob gates on assessment.requiresApproval: when true and !input.__approvedByApproval, a pending ApprovalRequest is filed into the in-memory approvals Map and persisted at cacheDir/approvals/<id>.json. The mobile provenance fields (sourceDeviceId, projectId, idempotencyKey, actionType, envelopeId, envelopeText) ride on the approval so decideApproval can re-dispatch the original job later.
- cacheDir/audit.jsonl receives an auditKind=approval_requested entry for every gate fire; chmod 600 honours the owner-only-audit owner decision from /Users/mose/.claude/plans/devhub-mobile-stage-b.md.
- decideApproval gains a dispatchApprovedJob hook that fires after a mobile_pairing approval is approved. The hook re-enters createControlJob with __approvedByApproval set, which short-circuits the gate. The original envelope text is replayed from the persisted approval so the control plane ends up with a real job in the same envelope-id lane.
- createControlPlane is now a thin wrapper around buildControlPlaneSurface(), which itself builds the surface and then back-fills decideApproval with a closure over surface.createJob. This breaks the createJob <-> decideApproval TDZ cycle that the previous architecture would have hit.
- decideApproval returns the approval record with dispatchedJobId populated for mobile approvals; rejected approvals leave dispatchedJobId null so the test suite can assert the gate did not fire.

services/control-plane/test/requires-approval.test.mjs (new, 5 cases):
