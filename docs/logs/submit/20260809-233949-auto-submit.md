fix(workbench): tokenize layout spacing and radius

## Commit Body

Workbench Layout css files (BreadcrumbBar, GlobalSearchDialog,
HeaderBar, RightSidebar, Sidebar, TabBar) and MainLayout still
hardcoded spacing in px for the high-frequency values 4/8/10/12/16
and radius 4/6/8/10, despite the @axi/tokens package already
exposing --axi-space-{1,2,2-5,3,4} and --axi-radius-{sm,md,lg,xl}.

Wrap each occurrence in var(--axi-*, <px>) so the design system
takes over once the layout files start following the canonical
token scale; until then the px fallback preserves the current
visual exactly.

Scope:
- Spacing tokenized: 4, 8, 10, 12, 16 px
- Radius tokenized: 4, 6, 8, 10 px
- Out-of-scale values (1, 2, 3, 5, 7, 9, 11, 13, 14, 20, 24 px) are
  intentionally left as raw px because there is no matching token;
  they should be consolidated by design in a follow-up

- pnpm --filter @axi/workbench build
- git diff --cached --check

  diff is expected)
- Full cross-browser matrix, Android packaging, production deploy

Confidence:
- High for typecheck/test/build; high for visual no-op because
  the fallback is the original px

Scope-risk:
- 7 layout css files only; page-level css (admin/*, Projects.css,
  ProjectDetail.css, etc.) is intentionally not touched in this
  PR to keep the diff reviewable. They have the same debt and

  the token scale, add it to @axi/tokens first rather than
  introducing a one-off px.
