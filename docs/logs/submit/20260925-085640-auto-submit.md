## Commit Body

The Workbench admin Observability page (apps/workbench/src/pages/admin/Observability.tsx)
calls /api/v1/observability/overview and /api/v1/observability/events?limit=50.
The api-gateway already forwards these paths to the foundation observability
control plane, but a misconfigured gateway leaves the Workbench page stranded
and the user sees an empty error banner.

- services/control-plane/src/server.mjs: new /api/v1/observability/* proxy
  block. The routes live BEFORE the catch-all coreAuth check (line 832)
  so the dev-server vite proxy can reach them without a gateway internal
  token. Each path forwards to ${AXI_OBSERVABILITY_URL}/api/v1/observability/...
  with x-axi-internal-token + x-axi-subject + x-axi-projects forwarded
  from the incoming browser request. On upstream failure the route
  returns 503 + { ok: false, degraded: true, error } so the page can
  surface a meaningful message instead of a 404.
- apps/workbench/vite.config.ts: add /api/v1/observability proxy rule
  pointing at the workbench control-plane (VITE_CONTROL_PLANE_PROXY_TARGET,
  default http://localhost:8092). Declared before the generic /api rule
  so the longest prefix wins regardless of insertion order. Production
  keeps routing through the api-gateway unchanged.
- services/control-plane/test/observability-proxy.test.mjs: 6 tests
  covering overview / events / events/:id / warning lifecycle POST /
