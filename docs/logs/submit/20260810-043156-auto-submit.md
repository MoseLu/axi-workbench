The sidebar, tab bar, breadcrumb chain and global search palette all read
their visible labels from three data files (navigationRegistry,
breadcrumbs, search-data) and the Axi shell type only accepts a
ReactNode for label, so we cannot thread t() through the existing
registry without breaking the shared shell contract.

Introduce a labelKey field alongside every literal Chinese label so
renderer code can call t(item.labelKey) without losing the canonical
fallback. The data layer is the source of truth for both fields; tests
continue to assert on the literal label.

- workbenchDesktopNavGroups becomes a strict shell-typed projection of
  a new workbenchDesktopNavGroupsWithKeys (group + item both carry
  labelKey). Shell consumers keep the old symbol; renderer code
  imports the with-keys variant.
- workbenchMenuRouteMap entries gain labelKey; resolveMenuRoute return
  type unchanged so the existing MainLayout call site keeps compiling.

- BreadcrumbItem / BreadcrumbNode / BreadcrumbRoute / SearchHit all
  carry labelKey / titleKey / subtitleKey next to the literal text.
- Tests continue to assert on the literal label.
