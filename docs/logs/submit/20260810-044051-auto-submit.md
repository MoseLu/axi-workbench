fix(workbench): migrate login page to i18n

## Commit Body

Login.tsx shipped every chrome string as literal Chinese (subtitle text,
error banners, success hint, button labels, resend countdown, expiration
banner). It is the very first page an unauthenticated user lands on, so
leaving it untranslated meant the entire en-US experience started in
Chinese.

Thread every literal through useI18n() under a new auth.login.* namespace.
Countdown and expiration copy that previously used template literals to
embed numbers ('60s 后可重新发送', '验证码将在 <date> 前有效') are split
into prefix / suffix keys so the dynamic value can be spliced in via
ordinary string concatenation, matching the OneTimeCodeInput approach
from earlier.
