fix(workbench): align i18n fallback with cool-admin locale order

## Commit Body

cool-admin-vue uses 'zh-cn' as the universal fallback locale so any active
language surfaces the canonical Chinese wording when a key is missing. The
current i18n t() flips the fallback based on the active locale (zh-CN
falls back to en-US, en-US falls back to zh-CN), which produces the
opposite of the documented behavior in a multi-language project where
English is the only second language and Chinese is the canonical source.

Route every missing key through the zh-CN dictionary first, then en-US,
then the caller-supplied fallback, then the raw key.
