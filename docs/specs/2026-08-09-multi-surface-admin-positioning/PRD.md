# 多端后台产品定位校准 — 变更 PRD

## 背景

`Axi Workbench` 已拥有两个独立用户应用，但现有的项目级 PRD 主要描述工程治理与入口隔离，尚未明确“谁在什么端完成什么管理任务”。这会让 Web 端被当作移动端的放大版，也会让移动端逐步承接完整后台。

## 目标

把项目级产品定位固化为：**Web 是完整后台管理主端；移动端是面向外出、提醒和轻操作的辅助管理端。** 该决定不改变两个独立应用的工程边界，也不把 DevSvc Host 或垂直工具并入用户后台。

## 成功标准

- `docs/state/PRD.md` 说明用户、场景、能力归属、跨端交接、非范围、阶段路线与可验收要求。
- 同名但语义不同的扫码能力被拆分为 Web 通用识别与移动审批确认。
- 移动导航以“4 个常驻页 + 扫码动作”的当前事实为准，不再写成五项底栏。
- TDD、TODO、Milestone、manifest、Handoff 和 Changelog 可追溯这项产品决策。

## 不做什么

- 不移动源码、不合并两套 React 路由树、不移除 `@epap/*` / legacy UI 兼容层。
- 不把当前产品文档草案误报为已完成功能实现或已完成用户研究。
