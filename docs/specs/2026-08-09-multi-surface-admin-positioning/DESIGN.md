# 多端后台产品定位校准 — 设计

## 核心决策

| 产品表面 | 定位 | 主要职责 | 明确不承担 |
| --- | --- | --- | --- |
| Web `apps/workbench` | 后台管理主端 | 复杂配置、全量查询、批量操作、流程编排、审计与系统治理 | 以移动底栏、扫码入口或窄屏卡片作为主交互模型 |
| Mobile `apps/workbench-mobile` | 辅助管理端 | 待办、告警、审批、所负责项目状态、扫码确认、个人设置 | 完整的租户/权限/全局配置和大批量管理 |
| DevSvc Dashboard | 本地 Host / 运维壳 | 本地服务与已托管工具的启动、状态和入口 | 第三个用户管理门户 |
| 垂直工具 | 专项能力表面 | 编码、验证码、Fleet、搜索、菜单助手等 | 用户后台的一级信息架构 |

## 约束

1. Web 与移动端保持独立入口、路由、页面和布局；仅共享认证会话、API 合同、语言偏好与 design tokens。
2. 产品能力的跨端共享必须是同一领域事实的不同操作方式，而不是复制页面。每项共享能力应写明 Web / Mobile / 双端、授权方式、审计事件和跳转交接。
3. Web 扫码是“通用识别与结果处理”；移动扫码是“已授权审批确认”。两者不得共用模糊命名或默认权限。
4. 实施从术语与能力台账开始，随后再逐页收敛，禁止用目录迁移或 viewport 分支制造表面统一。
